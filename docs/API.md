# API

Calibrated, gated, multi-head classifiers on top of text embeddings: train in Node, ship a small
JSON artifact, and score it at runtime with the same code that evaluated it.

It is built for decisions where **you must know how often the model is wrong before letting it
act**, such as routing, prioritisation, moderation or escalation. Each label gets its own head: a logistic
regression on the embedding, calibrated to the label's production prevalence. Its threshold comes
from an explicit recall or precision policy, and it must pass release gates before an artifact may
be enforced.

Built on [`@liquidau/solvers`](https://www.npmjs.com/package/@liquidau/solvers), which is verified against scikit-learn.

## Pipeline

```
embeddings ─► trainHeads ─────────────────────────────► ClassifierArtifact (JSON)
              train split:       fitLogistic (class-balanced, L2)        │
              calibration split: Platt | isotonic @ prevalence           │  validateArtifact
                                 pickThreshold(policy)                   ▼
              test split:        evaluateHead + gateHead      scoreEmbedding ─► decide(policy)
```

| Export | What |
|---|---|
| `trainHeads` | Fit, calibrate, threshold, evaluate and gate every head. Pure: you supply the embeddings, a split per example, and a binary target per head (`null` leaves an example out of a head) |
| `HeadPolicy` / `pickThreshold` | `recall`: the threshold reaches `designRecall` on calibration positives, set above the test gate's `targetRecall`, and is capped by a `maxFalseAlarm` budget. `precision`: the threshold is the target precision |
| `evaluateHead` | Recall with a Wilson 95% CI, false-alarm rate, prevalence-weighted precision and ECE, reliability table, distinct positive groups, recall per slice, and a comparison with an optional **baseline** (e.g. existing rules) including combined recall |
| `gateHead` | Release gates: minimum positives, recall, CI lower bound, beats the baseline, precision, minimum fired (`minFired`), ECE. Too few distinct groups, or fewer than 30 positives / fired examples with no explicit minimum, produces a warning |
| `background` (`trainHeads`) / `budgetThreshold` | Raise a head's threshold until it fires on at most a given share of ordinary background traffic, before test evaluation, so the gates judge the shipped threshold. Labelled test sets rarely contain enough ordinary text to show the false alarms that matter |
| `weak` / `maxWeakShare` (`trainHeads`) | Extra **weak positives** for the train split only (e.g. rule-miner's `weakLabels`), each weighted in [0, 1], total capped at `maxWeakShare` (λ, default 0.5) × the head's gold train positives. An embedding identical to a calibration, test or background row is refused. Class balancing is sample-weighted, so weak positives take λ / (1 + λ) of the positive class's weight instead of adding to it. `weakLabels` in the result (count, weight, cap, per rule, rule-set version and hash) belongs in `artifact.training.weak_labels`, and `reportMarkdown` shows it |
| `mode` (recall `HeadPolicy`), `conformalThreshold` | How a recall head's threshold is chosen. `heuristic` (default) is the `designRecall` margin and guarantees nothing. `conformal-expected` and `conformal-pac` pick it from order statistics of calibration positives (one per group), so production recall ≥ `targetRecall` in expectation, or with probability 1 − `delta`. `maxFalseAlarm` and any background budget are certified the same way, with δ split across them. If the limits cross, the head fails with the reason. `auto` takes the strongest guarantee the data supports. It falls back for lack of data with an *inconclusive* warning (to no guarantee at all only while `allowHeuristicFallback` is true, the default), and fails rather than drop PAC for the false-alarm budget. `evaluation.sufficiency` says why. Guarantees need each class's calibration examples to be exchangeable with production ones; prevalence may differ |
| `certified` (`evaluateHead`) | Exact Clopper–Pearson bounds from the test split, valid whatever chose the threshold: recall lower and upper, false-alarm upper, and precision lower at production prevalence. Groups count once. Plus a background-rate upper bound that stays valid when the background set the threshold. Under a conformal guarantee, the recall gate fails only when the test split contradicts it |
| `type` (`HeadInput`), `HEAD_TYPES`, `headChoice` | A head's type. `auto` (default) picks one of the others per head, as below; `linear` is a logistic head on the embedding (use it when X isn't an embedding, or the artifact must not hold training embeddings). `knn` scores a message by its mean cosine to the 10 nearest labelled positives minus the 10 nearest negatives; `stack` blends a linear logit, that knn score and a knn score on 50 principal components. Both learn their layer on **out-of-fold** features (3 folds by `foldKeys`, default `groups`), so a training row is never scored against itself, and both score against `result.reference`, which must ship as `artifact.reference` (`assertRoundTrip` catches a missing one). `auto` picks the type with the lowest 3-fold cross-validated guarantee cost on the training rows (false alarms at the target recall, or recall lost at the target precision; ties go to the simpler type) and records the costs in `result.headChoice`. A knn or stack head must beat linear's cross-validated cost by `autoMargin` (default 20%), so noisy near-ties keep the simpler linear head. Calibration, thresholds, guarantees and gates are unchanged for every type. knn suits clustered labels and does poorly on diffuse ones; no type wins every label, which is what `auto` is for. Non-linear heads don't take weak positives. **A knn or stack artifact contains training embeddings**, which can be partly inverted to text: treat it as data derived from training messages ([DATA.md](DATA.md)). Runtime cost: one pass over the reference per message, plus decoding the reference (and a one-off projection per stack head) on first use. Measured with 3,456 reference rows at 768 dimensions in Node: the artifact is 14.2 MB of JSON with `referenceEncoding: 'f32'` (default) or 3.6 MB with `'int8'` (thresholds and false alarms essentially unchanged); the first call takes about 90 ms (f32) or 30 ms (int8); each message about 4.6 ms on an Apple laptop (almost all of it the similarity scan, so it grows with rows × dimensions). A linear head stays in microseconds |
| `finer` (`HeadInput` and `trainHeads`), `FinerModel`, `FINER_C`, `FINER_SCALE` | **The finer-label route score**, off by default, for routes that are unions of a finer label (intents under "needs a person", flows under "account access"). Pass `finer: { labels }` to `trainHeads` (each row's finer label, null where unknown) and `finer: true` on a head. One multinomial L2 logistic model over the finer label (`C`, default `FINER_C` = 0.01, on the embedding standardised over its rows, folded into the stored weights) is fitted on the training rows that carry a finer label and shared by every finer head; `result.finer` must ship as `artifact.finer` (`buildArtifact` does it; `validateArtifact` refuses a finer head without it). Each finer head is linear on the embedding plus `scale` (default `FINER_SCALE` = 0.25) × logit(Σ P(finer label \| x) · route rate), with route rates from its training rows that carry both labels, smoothed toward their overall rate. The training rows the model was fitted on get **out-of-fold** probabilities (5 folds by `foldKeys`), so a row never scores itself. Calibration, thresholds, guarantees and gates are unchanged. In the lab (stages SL and JC, 10 October; mpnet and EmbeddingGemma, 9-10 seeds each) it lowered false alarms at the recall guarantee on Banking77 `urgent` (mpnet 1.11% to 0.36%, guaranteed on 10/10 seeds instead of 8/10), ABCD `access` and ToxicChat `toxic`, raised ABCD `refund`'s recall at precision 0.8 (0.658 to 0.765), and cost no head a guarantee. Where the route cuts across the finer labels (CFPB, ToxicChat `jailbreak`) it gave nothing. Rows labelled only with a finer label (an existing taxonomy on past messages) can be passed as training rows: they fit the shared model and give route rates for heads they are labelled for. Runtime cost: one K × d matrix product per message (K finer labels), shared by the finer heads; artifact size grows by K × d numbers (77 × 768 for Banking77's intents). Training cost: six multinomial fits by L-BFGS (the model and five folds), about 15 minutes for 77 finer labels on 3,456 rows at 768 dimensions in Node; each fit stops at 200 iterations, and a fold that stops there is reported as not converged |
| `standardize` (`trainHeads`) | Fit linear and finer heads on the embedding standardised per dimension (mean and sd over X and `background.X`, features only), folded back into raw weights, so artifacts and runtime are unchanged. It changes what the L2 penalty shrinks. With `C: 0.01` it is the lab's "recipe" (stage JC): it lowered false alarms on EmbeddingGemma (ABCD `access`, Banking77 `urgent`, ToxicChat `toxic`) but cost a head on mpnet, so it is off by default: measure on your encoder before adopting it |
| `dismissal` (`HeadInput`) | Certified dismissal rules in front of a head (rule-miner's `mineDismissals` / `certifyDismissals`). Rows a rule cleared score 0 in calibration, test and background, so a positive the rules dismissed counts as a miss: the head's guarantee covers rules and classifier together. Calibration is fitted on the rows the rules leave to the classifier; a target that would need cleared messages to fire fails the head. Recorded as `HeadSpec.dismissal`; cleared rows are left out of `testProbabilities` (runtime never scores them). Opt-in, and worth it on clustered labels, where certified rules can clear a large share of traffic; on diffuse labels few rules certify and the head may lose its guarantee |
| `reviewEpsilon` (`trainHeads`) | A conformal review floor: at most ε of positives score below it in expectation, so automatic dismissals have a stated miss rate |
| `ExampleRecord`, `validateProvenance`, `capTrainingWeights` (`records` on `trainHeads`) | Where every example came from. Only probability-sampled, human-labelled real traffic may calibrate or test (P1). Background is unlabelled traffic with one use (P2). A group stays in one role (P3). Retrieved and generated data are training-only (P4); near-duplicates of evaluation records are dropped (P5). Retrieved positives are capped at 50% and generated hard negatives at 30% of a head's training weight, and per rule (P6). Generated records need verification or an accepted batch (P7). Violations throw `ProvenanceError`; overrides are recorded and fail the release gate |
| `designSample`, `labelQueue`, `applyReviews`, `designOf` | A stratified probability sample of a traffic frame (rule firing × score band × optional slice), split into train, calibration and test before labelling. One blinded labelling queue: reviewers see an id, the text and the heads, nothing else. Inclusion probabilities are recomputed from what was actually labelled; skip rates are reported. Scores in the frame must come from text only. Allocation `expected-positives` keeps proportional shares and throws unless `total` is large enough for every stratum holding ≥ 2% of positives to expect 10 calibration positives, using rates from a prior round. In simulation, over-sampling high-score strata (the usual way to find positives) made design-based recall bounds fail in 57% of feasible runs, while sized proportional allocation held at 3.7% for δ = 5%. `allocation.topFactor` (proportional only) oversamples the top score band; it is safe only when the frame's scores come from a model independent of the head being certified, such as an offline LLM teacher run in batch (×2–×4 can substantially cut false alarms at a recall guarantee), and every factor above 1 adds a warning saying so. Allocation `neyman` sets n_h ∝ N_h·√(p_h(1 − p_h)) from a prior (a prior round, or an offline teacher's mean score per stratum, fixed before drawing), within the same floors and caps, putting labels where the label is uncertain. On real score shapes with Clef's scores as the prior it reached recall guarantees with far fewer labels than proportional or ×2 oversampling, at much lower false alarms; misses on later traffic reached 6.2% at 1,200 labels in one head, so check guarantees at large budgets |
| `mode: 'design'` (recall `HeadPolicy`), design-based evaluation | With sampled records, calibration is weighted by 1/π, which already reproduces production prevalence, so `prevalence` must not be passed. The `design` mode sets the threshold with solvers' `designRiskThreshold` (`designMethod` `exact` or `linearised`). Test metrics become Horvitz–Thompson estimates with linearised and bootstrap intervals, and the gates count Kish effective positives. Conformal modes refuse unequal inclusion probabilities |
| `retrieveFromSeeds`, `seedStats` | Real candidates near verified positives (cosine floor, MMR diversity), excluding labelled, reserved and evaluation-near-duplicate items, for labelling as training data. Seeds with a hit rate below 0.1 after 10 labels are retired |
| `realHardNegatives`, `selectForReview`, `verifyBatch` | Real rule-firing negatives from training data; generated batches accepted when the Wilson lower bound on reviewer agreement is ≥ 0.9 (96/100 passes, 95/100 fails). `publishPlan` refuses to promote an artifact trained on generated data without acceptance evidence |
| `defineAxes`, `coverageReport`, `checkSliceAxes` | Where real labelled data is thin: per-value and pairwise counts, and the positive groups each observable slice needs for a zero-miss guarantee. Tags are approximate and used only in this report |
| `mergeSmallStrata` (`designSample`, default on) | Strata too small for 2 calibration and 2 test items are merged before sampling: an adjacent band with the same rule firing and slice first, then across slice, then across rule firing. The design records which cells were merged. Decided from frame counts only, so estimates stay unbiased |
| `monitorWindow` | Drift checks for a deployed head. Exact binomial tests on the live share at or above the threshold (against the certified background bound) and at or above the review floor (against a reference), in both directions, with Bonferroni across the four tests. In simulation they caught new high-scoring topics and lost firing that a KS test on the whole score distribution missed, with no false alarms in 400 windows. Label meaning can't be monitored without fresh samples |
| `mode: 'design'` (precision `HeadPolicy`) | A precision threshold with a design-based guarantee from sampled calibration records. Candidates come from training scores, so they're fixed before calibration. In simulation the heuristic precision threshold missed its target in 95% of runs when Platt was misspecified; the design threshold held it |
| `sliceGate` (recall `HeadPolicy`) | Fails a slice whose recall is demonstrably below target (upper bound below target, Bonferroni across slices), warns when it can't be confirmed or has too few positives. With a slice at 0.80 against a 0.9 target it failed 99.9% of runs, where the overall recall gate failed 29% |
| `calibration_test`, `calibrationAlpha` | Cox's recalibration test on the test split, always reported; `calibrationAlpha` makes it a gate. At 2% prevalence the ECE > 0.05 gate never fired, even for clearly miscalibrated probabilities. Cox kept a 5% false-rejection rate and caught shifted, overconfident and top-inflated probabilities |
| `stratumOf` (`designSample`) | Every frame item's stratum, keyed as `designOf` keys strata. Population-level facts (e.g. how often a deterministic rule fires in each stratum) can then sharpen design-based bounds |
| `requiredSampleSize`, `allocation.priors` | The smallest `expected-positives` total, computed without drawing. Priors for several heads give a total that satisfies every head. A stratum counts as material only if the prior round saw positives in it |
| `buildArtifact` | The artifact for a training result, with `gates` taken from it (passed exactly when no gate failed), plus the reference, head choices, convergence, provenance, design and weak-label summaries. Use it rather than assembling an artifact by hand, so the gates can't be set by mistake |
| `requireConvergence`, `result.convergence` (`trainHeads`) | Whether each head's logistic model (and a stack's linear component) and its Platt calibrator converged. A fit that didn't is a warning by default and a gate failure with `requireConvergence: true`. Non-convergence is rare (the Platt fit is lightly regularised, so even separable scores settle); this is a safety net |
| `assertRoundTrip` | Serialise, reload and re-score the artifact, so what was evaluated is exactly what will run |
| `EmbeddingSpec` (`layers`, `pooling`, `layer_normalize`, `precision`, `max_chars`), `checkEmbeddingSpec` | What the heads' vectors are: the model, and for multi-layer features the layers pooled and concatenated (mean pooling, optionally each layer unit-normalised), the model's numeric precision, and the character limit before tokenising. `checkEmbeddingSpec(artifact, runtimeSpec)` lists every difference from the runtime's embedder; vectors of the right width can still come from another layer set or precision, so refuse to serve while it is non-empty |
| `EmbeddingSpec.context`, `featureWidth` | **Context features**: heads trained on a message's embedding followed by its context's (the conversation's next turn, an assistant's reply), each from its own encoder. Train on the concatenated vectors as usual, and record the context's encoder as `embedding.context` (a spec of its own, not nested further). The heads' input width is then `featureWidth(spec)` = `dimensions + context.dimensions`; `scoreEmbedding` takes the two vectors concatenated, message first, and `checkEmbeddingSpec` compares the context's spec too. @liquidau/router serves it with a `contextEncoder` and each request's `context`. Document classifiers take no context. In the lab it was the largest single gain on ABCD `access` (RESEARCH.md stages CX and GX); an mpnet context beside an EmbeddingGemma message did as well as an EmbeddingGemma context, at a tenth of the cost |
| `validateArtifact`, `scoreEmbedding`, `calibrate` | Runtime loading and scoring. Small and dependency-light. `validateArtifact(raw, { mode: 'enforce' })` refuses an artifact whose gates didn't pass or weren't recorded; in any mode it refuses gates that say passed while recording failures, and isotonic tables that aren't non-decreasing maps of [0, 1] into [0, 1]. `decide` refuses scores outside [0, 1]. `validateArtifact` checks knn and stack heads against the artifact's reference, including that every decoded reference value is finite; older loaders refuse such heads (their weights don't match the embedding's width) instead of mis-scoring them |
| `settleWithRules`, `checkRuleSetPairing` | **Two tiers.** `settleWithRules(policy, matcher.evaluate(text))` decides a message from rules alone when that is what `decide` would return whatever the scores (every policy head dismissed; or a firing rule's head comes after only dismissed heads and nothing undismissed can suppress it), else returns what to forward to the model tier. A randomised test checks the two paths agree on every decision. `checkRuleSetPairing(artifact, ruleSetHash)` names heads certified with another dismissal rule set (record rule-miner's `ruleSetHash` as `dismissal.ruleSet`); the model tier should refuse to serve while it is non-empty. See [SERVING.md](SERVING.md) |
| `decide` / `missingPolicyHeads` | Priority order plus suppression rules, e.g. "the scope heads can't fire while any priority head is in its review band". `decide` throws on a missing or non-finite score, except for heads passed as dismissed (a certified dismissal rule cleared them for this message: no score needed, they never fire or suppress). `fired` (a certified firing rule's head, under a "rules or classifier" policy) counts as at its threshold; such a decision has reason `'rule'`. The embedding can be skipped only when every head is decided by a rule. Policy heads the artifact lacks never fire or suppress; check them once at startup with `missingPolicyHeads` |
| `loadOrder`, `refuseToServe`, `publishPlan` | **Deprecated** (supported until an announced breaking release): complete releases are built with `@liquidau/router`'s `buildRelease` and loaded with its `loadRouter`. Artifact lifecycle: a promoted artifact (must pass its gates) is enforced; a shadow candidate (may fail its gates) is only ever scored in shadow mode |
| `routerRuleSetHash`, `RouterTraining`, `buildArtifact(..., { router })` | The router pairing record, `training.router.ruleSetHash`: rule-miner's `ruleSetHash` of the complete rule set the artifact was trained and evaluated with. `validateArtifact` refuses a malformed record; `@liquidau/router` refuses a release without it |
| `prepareScoring` | Builds a knn/stack artifact's runtime state (decoded reference rows, stack projections) at start-up instead of on the first request. Don't mutate a prepared artifact |
| `DecisionHeads` | What `decide` and `missingPolicyHeads` read: per-head `threshold` and `review_floor`. An artifact is one; so is a restricted projection |
| `reportMarkdown` | A human-readable report of the gates and every head |
| `CachedEmbedder`, `truncateText`, `hashEmbedding` (from `/embedder`) | Embedding with a provider-agnostic on-disk cache (Node only): one text per call (`embed`) or batched (`embedBatch`, `batchSize`); atomic saves under a lock file, so several processes can share one cache; optional `dimensions` check; `format: 'binary'` (an append-only file of key + float32 vector records, needs `dimensions`; earlier two-file caches are converted on first use) for caches past ~50,000 vectors, where the JSON file slows down and finally can't be saved (V8's ~512 MB string limit). `truncateText` is the surrogate-safe truncation the cache uses - call it at runtime too; it is also exported from the package root, which serving code should use (see [SERVING.md](SERVING.md)). Plus a deterministic fake embedding for pipeline tests. `EmbeddingSpec.input_type` records provider input types (e.g. Cohere `classification`) |

## Edge tier

Cheap scorers that settle confident messages before the embedding model, certified with the same
claims as rules (liquidau-lab stages ET, MX and EL, 9 October).

| Export | What |
|---|---|
| `trainEdge` | Per head, a cross-fitted logistic blend of `rules` (whether a certified rule for the label fired), `lexical` (hashed n-grams), `static` (a static embedding) and `vector` (any other host vector, e.g. MiniLM). Certifies on the calibration design: fire when the blend is above `fire` (≤ `maxFalseAlarms` of negatives, default 0.005) and dismiss when below `dismiss` (≤ `maxDismissed` of positives). Returns the `'liquidau-edge/1'` document, its digest, and per head the rows it fires and dismisses (for `trainHeads`). `maxDismissed` may be a list (a ladder, e.g. full, half, fire-only): one candidate per share in `rungs` |
| `edgeLadder`, `assembleEdge`, `edgeHeadDigest` | A head's candidates as `HeadInput.edge`; the document with each head's chosen candidate (`trainHeads`' `edgeChoice`); one head's model digest, which the head's record names |
| `HeadInput.edge` (`trainHeads`) | The edge's rows for this head: dismissed rows score 0 (a dismissed positive is a miss), fired rows score 1, on calibration, test and background, so the head's guarantee covers the edge and the head together. A list is a ladder: the first candidate with which the head passes its gates with a guarantee is kept (`result.edgeChoice`), so the edge never costs a guarantee a smaller dismissal share would keep. An edge that decides every calibration row leaves the calibrator nothing to fit: `trainHeads` throws `CalibrationRemainderError`, and a ladder skips that candidate (with a warning) unless it is the last. The head records `edge: { model_sha256 }` |
| `scoreEdge` | The blended score and decision per head at runtime (the router's edge tier calls it) |
| `validateEdge`, `edgeDigest`, `EDGE_SCHEMA`, `EDGE_SCORERS` | Validate an edge document; its canonical SHA-256 |
| `evaluateHead` `scored` | Rows the head scored itself: calibration diagnostics (ECE, reliability, the Cox test) use only these; `calibration_rows` records the count. trainHeads passes it whenever rules or the edge decide rows first |
| `checkEdgePairing` | Heads certified with another edge model than the release's document runs, or an edge model for a head not certified with it: refuse to serve while non-empty |
| `HeadPolicy.reserve` (recall) | Recall held in reserve for later periods: the threshold is certified at `targetRecall + reserve`; gates and the promise stay at `targetRecall`. Default 0. In the lab a 0.02 reserve held ToxicChat's later-period promise in 18 of 20 seeds (13 without) for about 2 points of false alarms, and cost ABCD and ADE false alarms for no gain |

## Middle tier

A cheaper encoder's head that fires and dismisses between the edge and the main encoder, kept per head
only where training says it pays (`middle.ts`; liquidau-lab stages CC and DY, 10-11 October: edge → mpnet
→ EmbeddingGemma).

**Off by default, and it costs gate passes.** In liquidau-lab stage DZ (13 October) the cascade cut the
cost per message by 25-80%, but it shipped fewer guaranteed heads: on ADE 0-2 of 10 seeds against 6 for
edge → main encoder, on ToxicChat `toxic` 6-7 against 9. Promises held as often; the losses were gate
failures (mostly ECE). Behind both tiers, the main head is calibrated and certified on a smaller, harder
remainder. The training-row choice cannot see this: at point thresholds the edge alone often reaches the
recall target on training rows, so the choice reads no main-head false alarms on what the edge leaves.
Use it only where latency matters more than how often a release passes, and keep edge → main encoder
as the fallback when a cascade head fails a gate.

```ts
const edge = trainEdge({ ..., heads: [{ name, y, maxDismissed: 0.5 * (1 - target) }] });   // one candidate, no ladder
const mid = trainHeads({ X: middleVectors, ... }).heads[name]!;                            // the middle model, trained by the host
const middle = trainMiddle({ embedding: middleSpec, vectors: middleVectors, split, groups, design,
  heads: [{ name, y, model: { coef: mid.weights, intercept: mid.bias }, targetRecall: target, edge: edge.rungs[name]![0] }] });
const result = trainHeads({ X, ..., heads: [{ name, y, policy, edge: edgeRows, cascade: cascadeInput(edge, middle, name)! }] });
const middleDoc = assembleMiddle(middle, result.cascadeChoice);                           // null when no head kept it
```

| Export | What |
|---|---|
| `trainMiddle` | Certifies each head's middle thresholds behind its edge candidate on the calibration sample, with the edge's decisions pinned. The budgets are CUMULATIVE: fires at most `maxFalseAlarms` of negatives (default 1%, the edge's included), dismissals at most `maxDismissed` of positives (default the edge's share + 0.25 × (1 − target)). The middle decides only rows the edge left. Returns per head the model, the combined rows, its digest, cross-fitted training scores (5 folds by group, C = 1, balanced) and the budgets. Recall heads only; `embedding.precision` is required |
| `HeadInput.cascade` (`trainHeads`) | The per-head choice, made from the training rows only, before calibration (`chooseCascade`). Kept: the head is certified behind both tiers and records `middle: { model_sha256 }`. Not kept: behind the edge alone. `choice: 'cascade' \| 'edge'` fixes the outcome; decide it before training. It needs a single edge candidate, since the ladder was not validated with the middle tier. The decision and both costs go to `result.cascadeChoice`, stored as `artifact.training.cascade_choice` |
| `cascadeInput`, `assembleMiddle` | HeadInput.cascade from trainEdge's and trainMiddle's results; the middle document with the heads that kept it |
| `chooseCascade`, `cascadeCost`, `crossFitScores`, `CASCADE_TOLERANCE` | The choice as a pure function. Every tier's thresholds are re-derived on the training rows from the budgets, then false alarms are compared at min(0.99, target + reserve) without splitting tied scores. The cascade is kept when its cost is at most 1.1 × the two-tier cost + 0.001, the rule fixed before stage DY's results. A better rule needs fresh seeds |
| `scoreMiddle`, `validateMiddle`, `middleHeadDigest`, `middleDigest`, `MIDDLE_SCHEMA` | Runtime score and decision per head (it checks the vector's width and finiteness); validation; per-head digests that cover thresholds and claims. `claims.prior_edge_sha256` names the edge model the thresholds were certified behind |
| `checkTierPairing` | `checkEdgePairing` plus the middle tier: certified middle digests, middle heads certified with it, and the edge each middle model sits behind. Refuse to serve while non-empty |
| `TrainEdgeResult.trainScores` | Out-of-fold blend scores on each head's training rows (NaN elsewhere), aligned with the rows: the edge's input to the choice |

Caveat: the edge, middle and head thresholds are each certified at δ on the same calibration rows,
chained. Without a split or a union bound, the joint confidence is below 1 − δ. The edge ladder adds a
selection of its own: it keeps the first candidate that passes its gates, which spends calibration and
test labels more than once. DATA.md's recommendation of a larger calibration share applies.
